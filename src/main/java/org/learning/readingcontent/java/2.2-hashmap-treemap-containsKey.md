# HashMap vs TreeMap: `containsKey()` Method – In Detail

The `containsKey()` method in both `HashMap` and `TreeMap` checks whether a given key exists in the map. While their purpose is the same, **they differ significantly** in internal implementation, performance, comparison mechanism, and null handling.

---

## 🔍 `HashMap` vs `TreeMap` — `containsKey()` Method

| Aspect | `HashMap.containsKey()` | `TreeMap.containsKey()` |
|--------|--------------------------|--------------------------|
| **Data Structure** | Hash table (array + linked list/tree for collision buckets) | Red-Black Tree (Self-balancing binary search tree) |
| **Time Complexity** | Average: **O(1)** <br> Worst-case: **O(n)** (in case of poor hash distribution or DOS attack) | Guaranteed **O(log n)** |
| **Comparison Mechanism** | Uses `hashCode()` and `equals()` | Uses `compareTo()` (natural ordering) or a provided `Comparator` |
| **Key Requirements** | Must implement `hashCode()` and `equals()` consistently | Must implement `Comparable` or be handled by a `Comparator`; must be consistent with `equals()` |
| **Null Handling** | Allows **one null key** | **Does not allow null key** (throws `NullPointerException` if used with natural ordering) |
| **Ordering** | **No ordering** guarantee | Keys are **sorted** (ascending by default) |
| **Thread Safety** | Not thread-safe | Not thread-safe |

---

## 🔸 `HashMap.containsKey(Object key)`

### ✅ Internal Working:

```java
public boolean containsKey(Object key) {
    return getNode(hash(key), key) != null;
}
```

- **Step 1:** Computes the hash of the key using `hashCode()`
- **Step 2:** Finds the appropriate bucket index
- **Step 3:** Iterates through the bucket (linked list or tree) using `equals()` to match the key

### 🔁 Example:

```java
Map<String, Integer> map = new HashMap<>();
map.put("one", 1);
System.out.println(map.containsKey("one")); // true
```

---

## 🔸 `TreeMap.containsKey(Object key)`

### ✅ Internal Working:

```java
public boolean containsKey(Object key) {
    return getEntry(key) != null;
}
```

- Uses **binary search** on the Red-Black tree
- Relies on `compareTo()` or custom `Comparator.compare()` to navigate the tree and find the key

### ⚠️ If the `Comparator` or `Comparable` implementation does not behave correctly, it may:
- Miss keys that exist
- Throw `ClassCastException` or `NullPointerException`

### 🔁 Example:

```java
Map<String, Integer> treeMap = new TreeMap<>();
treeMap.put("one", 1);
System.out.println(treeMap.containsKey("one")); // true
```

---

## 🔸 Null Key Behavior

| Behavior | `HashMap` | `TreeMap` |
|----------|-----------|-----------|
| `put(null, val)` | ✅ Allowed (only one `null` key) | ❌ Throws `NullPointerException` (unless custom Comparator handles null) |
| `containsKey(null)` | ✅ Allowed | ❌ Throws `NullPointerException` |

---

## 🔸 Comparison Consistency Requirement

| Requirement | `HashMap` | `TreeMap` |
|-------------|-----------|-----------|
| Comparison | `equals()` must be consistent with `hashCode()` | `compareTo()` or `Comparator` must be consistent with `equals()` |
| Why it matters | Otherwise, duplicate keys or lookup failure | Keys might not be found even if they exist (incorrect tree traversal) |

---

## 🔸 Practical Use Case Differences

| Use Case | Prefer `HashMap` | Prefer `TreeMap` |
|----------|------------------|------------------|
| Fast access by key (unordered) | ✅ Yes | ❌ |
| Need to maintain sorted order of keys | ❌ | ✅ Yes |
| Frequent `containsKey()` calls for large map | ✅ (faster average case) | ❌ (slower) |
| Range queries (e.g. `subMap`, `ceilingKey`) | ❌ Not supported | ✅ Efficient and supported |
| Null keys required | ✅ Supported | ❌ Not supported by default |

## 🔸 Example with Custom Class

```java
class Person {
    String name;
    public Person(String name) { this.name = name; }

    public boolean equals(Object o) {
        return (o instanceof Person) && ((Person) o).name.equals(this.name);
    }

    public int hashCode() {
        return name.hashCode();
    }
}
```

✅ With `HashMap`, only `equals()` and `hashCode()` are required:

```java
Map<Person, Integer> map = new HashMap<>();
map.put(new Person("John"), 1);
map.containsKey(new Person("John")); // true
```

❌ With `TreeMap`, we must implement `Comparable<Person>` or provide a `Comparator`:

```java
class Person implements Comparable<Person> {
    String name;
    public int compareTo(Person p) {
        return name.compareTo(p.name);
    }
}
```
