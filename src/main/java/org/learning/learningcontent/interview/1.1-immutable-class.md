# Creating an Immutable Class in Java (Java 17+)

## Why Use Immutable Classes?

Immutable classes are classes whose instances cannot be modified after construction. They offer several benefits:

* **Thread safety** without synchronization
* **Safe sharing** of objects across classes and threads
* **Predictability** and ease of reasoning
* **Safe usage** as keys in hash-based collections

---

## Best Practices to Make a Class Immutable

### 1. Declare the Class as `final`

This prevents other classes from extending it and potentially breaking immutability.

```java
public final class Employee {
    // ...
}
```

### 2. Make All Fields `private` and `final`

* `private`: restricts direct access from outside the class
* `final`: ensures the field is assigned only once

```java
private final int id;
private final String name;
private final LocalDate joiningDate;
private final List<String> skills;
```

### 3. Initialize All Fields via Constructor

All data should be initialized during construction to ensure consistency.

```java
public Employee(int id, String name, LocalDate joiningDate, List<String> skills) {
    this.id = id;
    this.name = name;
    this.joiningDate = joiningDate;
    this.skills = List.copyOf(skills);
}
```

### 4. Do Not Provide Setters

Do not expose any setters or mutator methods that allow modification of internal state.

```java
// Do NOT include this:
public void setName(String name) {
    this.name = name;
}
```

### 5. Defensive Copy of Mutable Inputs

Make defensive copies of mutable objects (e.g., `List`, `Map`, `Date`) when assigning them.

```java
this.skills = List.copyOf(skills); // Java 10+
```

### 6. Return Defensive Copies of Mutable Outputs

Do not return internal mutable objects directly. Return a copy to prevent outside modification.

```java
public List<String> getSkills() {
    return List.copyOf(skills);
}
```

### 7. Use Immutable Types Where Possible

Prefer using types like `String`, `LocalDate`, `UUID`, which are inherently immutable.

### 8. Override `equals()`, `hashCode()`, and `toString()`

Helps with logical equality, hashing behavior, and debugging/logging.

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Employee)) return false;
    Employee other = (Employee) o;
    return id == other.id &&
           name.equals(other.name) &&
           joiningDate.equals(other.joiningDate) &&
           skills.equals(other.skills);
}

@Override
public int hashCode() {
    return Objects.hash(id, name, joiningDate, skills);
}

@Override
public String toString() {
    return "Employee{" +
           "id=" + id +
           ", name='" + name + '\'' +
           ", joiningDate=" + joiningDate +
           ", skills=" + skills +
           '}';
}
```

## Complete Example

```java
import java.time.LocalDate;
import java.util.List;
import java.util.Objects;

public final class Employee {

    private final int id;
    private final String name;
    private final LocalDate joiningDate;
    private final List<String> skills;

    public Employee(int id, String name, LocalDate joiningDate, List<String> skills) {
        this.id = id;
        this.name = name;
        this.joiningDate = joiningDate;
        this.skills = List.copyOf(skills);
    }

    public int getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public LocalDate getJoiningDate() {
        return joiningDate;
    }

    public List<String> getSkills() {
        return List.copyOf(skills);
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Employee)) return false;
        Employee other = (Employee) o;
        return id == other.id &&
               name.equals(other.name) &&
               joiningDate.equals(other.joiningDate) &&
               skills.equals(other.skills);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name, joiningDate, skills);
    }

    @Override
    public String toString() {
        return "Employee{" +
               "id=" + id +
               ", name='" + name + '\'' +
               ", joiningDate=" + joiningDate +
               ", skills=" + skills +
               '}';
    }
}
```

## Summary Checklist

| Best Practice                        | Purpose                                               |
| ------------------------------------ | ----------------------------------------------------- |
| `final` class                        | Prevents subclassing                                  |
| `private final` fields               | Ensures single assignment and no external access      |
| Constructor initializes all fields   | Guarantees a fully initialized, consistent object     |
| No setters                           | Prevents mutation                                     |
| Defensive copy of inputs and outputs | Prevents state mutation through external references   |
| Use immutable types                  | Reduces need for copying or guarding state            |
| Unmodifiable collections             | Prevents modification of internal collection state    |
| Override `equals()`, `hashCode()`    | Enables logical equality and correct behavior in maps |
| Override `toString()`                | Improves logging and debugging                        |

By following these practices, you can create robust, thread-safe, and predictable immutable classes in Java.
