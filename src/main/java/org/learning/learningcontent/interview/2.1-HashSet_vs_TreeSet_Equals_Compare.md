# Behavior of `equals()` and `hashCode()` in `HashSet` vs `TreeSet` (With Comparator)

## 🔹 Overview

Java provides two main types of sets:
- `HashSet`: Based on hashing.
- `TreeSet`: Based on a sorted tree structure (Red-Black Tree).

These two classes determine uniqueness **differently** for custom objects.

---

## 🔹 Behavior in `HashSet`

A `HashSet` relies on:
- `hashCode()` to **locate the bucket**
- `equals()` to **check for actual equality**

### ✅ What Happens Internally:
1. Computes the hash using `hashCode()`.
2. Finds the bucket in the underlying array.
3. Iterates through bucket elements using `equals()` to detect duplicates.

### 🧪 Example:

```java
class Employee {
    int id;
    String name;

    @Override
    public boolean equals(Object o) {
        return o instanceof Employee emp && emp.id == this.id;
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}

Set<Employee> hashSet = new HashSet<>();
hashSet.add(new Employee(1, "Alice"));
hashSet.add(new Employee(1, "Bob")); // Not added: considered equal
```

Even though the names differ, the same `id` causes the `equals()` method to treat them as duplicates.

---

## 🔹 Behavior in `TreeSet` (with Comparator)

A `TreeSet` uses:
- `compareTo()` if the object implements `Comparable`.
- Otherwise, a provided `Comparator`.

### ⚠️ Important:
- It **does not use** `equals()` or `hashCode()` to determine uniqueness.
- If `compare()` returns `0`, the object is considered a duplicate.

### 🧪 Example with `Comparator`:

```java
class Employee {
    int id;
    String name;

    public Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }
}

Comparator<Employee> byId = Comparator.comparingInt(emp -> emp.id);
Set<Employee> treeSet = new TreeSet<>(byId);

treeSet.add(new Employee(1, "Alice"));
treeSet.add(new Employee(1, "Bob")); // Not added: id is same, compare returns 0
```

The `TreeSet` treats both objects as duplicates because the comparator returns `0` (same ID).

---

## 🔄 `HashSet` vs `TreeSet` Summary

| Feature            | `HashSet`                      | `TreeSet`                        |
|-------------------|--------------------------------|----------------------------------|
| Uniqueness Check  | `hashCode()` + `equals()`      | `compareTo()` or `Comparator`   |
| Ordering          | ❌ No                          | ✔️ Yes (sorted)                  |
| Null Allowed?     | ✔️ One null                    | ⚠️ Only if comparator supports   |
| Performance       | O(1) for add/lookup (avg)      | O(log n)                        |
| Need to Override  | `equals()` and `hashCode()`    | `Comparable` or provide `Comparator` |

## 🧪 Example: Different Results in HashSet vs TreeSet

```java
class Person {
    int id;
    String name;

    public Person(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object o) {
        return o instanceof Person p && id == p.id && Objects.equals(name, p.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }
}

Comparator<Person> compareById = Comparator.comparingInt(p -> p.id);

Set<Person> hashSet = new HashSet<>();
Set<Person> treeSet = new TreeSet<>(compareById);

hashSet.add(new Person(1, "Alice"));
hashSet.add(new Person(1, "Bob")); // Added: names differ

treeSet.add(new Person(1, "Alice"));
treeSet.add(new Person(1, "Bob")); // Not added: same id → compare returns 0
```

### ✅ Output:

- `hashSet.size() = 2` (because `equals()` checks both `id` and `name`)
- `treeSet.size() = 1` (because comparator only checks `id`)

---

## 🔒 Hidden Contract Between `equals()` and `compareTo()` / `Comparator`

If a class is used in both `HashSet` and `TreeSet`, you should ensure:

### ✅ Consistency Rule:
> If `compareTo(a, b) == 0`, then `a.equals(b)` should also be `true`.

### ⚠️ If Violated:
- `TreeSet` might prevent duplicates that `HashSet` allows, and vice versa.
- Inconsistent or unexpected behavior in sorted collections and maps.

### 🛡️ Best Practice:
- If using custom `Comparator`, make sure it uses the same fields as `equals()` and `hashCode()`.

---

## ✅ Summary

| Collection | Uniqueness Logic         | Affected By |
|------------|--------------------------|-------------|
| `HashSet`  | `equals()` + `hashCode()`| Field logic in these methods |
| `TreeSet`  | `compareTo()` or `Comparator.compare()` | Comparison result only |
| Best Practice | Keep `equals()` and `compareTo()` consistent | Ensures no bugs in collections |
